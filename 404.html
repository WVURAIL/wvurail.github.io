A few places worth trying, and how to tell us about a broken link. --- {%- comment %} Port of the dark-theme 404 onto the Design System. Without this file GitHub Pages serves its own unbranded error page, which drops the visitor out of the site entirely — no navigation, no way back. SiteImprove flags broken links, and this is where they land. The permalink must be exactly /404.html: GitHub Pages looks for that file at the site root and serves it for any unknown URL. /404/ would not be found. The page is noindex and out of the sitemap for the same reason — it exists at every unknown address and should never be a search result. The old layout rendered `eyebrow:` and `lead:` from front matter; the wvu layout does not, so both live in the hero band below. Destination links use relative_url as the source did, so the page still works at any depth if the site ever gains a baseurl. The mailto subject derives from site.url exactly as the source does, so it follows the cutover to the University domain. {% endcomment -%}
